## 任务目标

在项目目录 `I:\deepseek\compony` 下，完成「Compony —— 以公司为模型的多子智能体协同系统」的开发，并配有可交互的前端面板。使用 git 进行版本控制，远程仓库为 https://github.com/wubumeishu/deepseek_test。

## 系统需求（完整清单）

1. **项目排期与版本管理**：任务排期、进行中/已完成项目、版本管理。
2. **HR 招聘与培训**：招聘员工、评估员工能力、新人培训；可提前设置招聘条件。
3. **组织架构（部门）**：部门可编辑、可自定义；提供常见部门/员工的模板系统；每个部门有自己的约束和专用工具；可设置部门负责人，负责人可点击查看当前负责的 agent。
4. **首页可视化**：一栋大楼或一个小房间（根据员工数和部门数量动态缩放）；员工有皮肤（如猫咪），思考时有气泡；前端展示工位。
5. **咖啡室/休息室**：模型需要冷却（如一分钟只能调用多少次、同一时段消耗量较大），冷却中的员工在此休息。
6. **会议室**：员工可跨部门讨论（区别于任务分配）。
7. **任务分配**：任务分配给部门 → 再拆解到具体员工。
8. **敏捷小队**：开发新功能时，从不同部门"横向"抽调员工组成项目组——1 个产品经理（负责人）+ 1 个 UI 设计师 + 3 个前端/后端开发 + 1 个测试工程师，完成后各自回到原部门。
9. **员工状态展示**：休息/工作状态；桌上本子高度直观显示待完成任务量（预计 ~42k token·大、~18k token·大 等档位）。
10. **问题库**：记录踩过的坑和犯过的错。
11. **日志与回溯**：所有操作必须备份清楚，防止捣蛋鬼或误操作导致不可回溯。
12. **UI 生成**：文生图、图生图、文生视频。
13. **底层可扩展 + 按需分配**：架构随时可兼容新模块，人员配置按需分配。
14. **看板**：任务看板视图。
15. **每日站会**：每天 10-15 分钟，每人回答三问——昨天做了什么？今天打算做什么？遇到什么阻碍？
16. **自动化监控**：Git 提交记录、测试发现的 Bug 数、燃尽图，实时显示在仪表盘。
17. **强制代码审查**：代码不能直接上线，必须由同级/高级工程师审查，写烂了直接打回。
18. **资源配额**：开局效果1=每分钟 160 次请求（每分钟重置）；效果2=每 5 小时 1500 次（每 5 小时重置）；两者可叠加。低价值需求排期、紧急事快速做，保护基层员工不被无效工作压垮。
19. **分支管理**：所有人不能直接改主干，各自拉分支；合并冲突必须手动解决，系统绝不擅自覆盖。
20. **强制 PR/Lint**：提交必须走 PR + 自动化风格检查，不合规直接拦截。
21. **自动测试守护**：红灯不合并——测试失败时代码无法进主干。
22. **架构物理隔离**：微服务拆分，模块间仅经严格 API 通信。
23. **技术债**：每个迭代预留 15%-20% 时间清理技术债。
24. **文档与交叉审查**：详尽开发文档 + 频繁交叉审查，确保无人不可替代。

## 关键约束（必须遵守）

1. **git 版本控制**：所有改动走 git；合并冲突绝不擅自覆盖；提交信息清晰。
2. **沙箱注意**：DSH 沙箱可能禁止 spawn `git.exe`（EPERM）。若遇此情况，git 提交/推送由用户本机执行（`git-commit.ps1`），或在 `danger-full-access` 模式下用真实 git.exe 操作。切勿在沙箱内手工构造 git 对象（SHA-1 可能被沙箱破坏导致仓库损坏）。
3. **代码品质**：严格类型（TS strict）、写测试、写文档。
4. **工作区**：默认 `I:\deepseek`，写外部路径需先请求授权。
